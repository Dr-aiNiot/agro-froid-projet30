1. Rôle et périmètre

M5 = B4 : transformer un pack de preuves B2 en une décision traçable, un JSON canonique, un calcul d'exposition et un package HITL signé. B4 ne planifie pas, ne cherche pas et ne rédige pas : il vérifie, calcule, applique la politique et prépare l'action humaine.

Le chemin est volontairement linéaire et déterministe. Aucun LLM n'intervient dans B4. Les seules sources de vérité sont la télémétrie vérifiée, la politique versionnée et le registre des certificats.

Machine à états HITL

ÉtatDéclencheurTransition
PROPOSEDB4 a calculé la décisionHITL requis → PENDING_HITL ; sinon COMMITTED
PENDING_HITLPackage émisApprobation → APPROVED ; rejet → REJECTED ; 30 min → EXPIRED
APPROVEDToken valide, rôle correct, nonce neufÉcriture ledger + outbox → COMMITTED
REJECTED / EXPIREDMotif ou délaiNouveau package possible, nonce différent
Anti-rejeu. Le token contient le hash du résultat et un nonce à usage unique. Modifier le token, rejouer le token ou changer le résultat produit une erreur : SIGNATURE_INVALIDE, TOKEN_DEJA_UTILISE ou RESULTAT_MODIFIE.

Exposition

E_lot = quantite × f_magasin × f_vente × f_delai. Score nominal : 60.0/100 (ELEVE), 2 lots, 2 magasins, 128 clients tokenisés. Le score sert à prioriser ; la décision vient de la politique.

Décisions structurantes

  1. B4 déterministe. Un LLM peut proposer, pas calculer un delta, une exposition ou une signature. T=0 ne suffit pas ; le code est la source de vérité.
  2. Pas de dépendance externe. Le jury peut rejouer M5 avec Python seul, sans clé API, sans réseau, sans Mongo.
  3. HITL structurel. Le token n'est pas un bouton : il est signé, lié au résultat, expirant et à usage unique.
  4. Preuves reproductibles. Chaque test écrit un artifact JSON et un hash. La matrice de traçabilité relie exigence, test et preuve.
Ce qui est mocké et ce qui ne l'est pas. Le pack B2, la télémétrie et les certificats sont des mocks contrôlés. Le code B4, la politique, le token, le ledger et les tests sont réels. Le mock permet de tester sans attendre B1/B2/B0.

Limites et suite

  • Le pack B2, la télémétrie et les certificats sont des mocks ; le branchement réel se fait par contrat, sans modifier B4.
  • Le token utilise un secret de démonstration ; en production, clé dans un coffre et rotation.
  • Le double contrôle RAPPEL est modélisé dans le payload ; l'écran deux acteurs reste à câbler.
  • DLQ et outbox sont simulés en JSON ; le retry réel sera branché avec B0.
